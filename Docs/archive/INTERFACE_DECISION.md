# Project Brain — CLI / MCP 선택

결정일: 2026-09-04

## 결정

AI의 주 인터페이스는 **로컬 stdio MCP 서버**로 한다. 사람은 Unity Editor UI를 사용한다. 독립 CLI는 MVP에서 만들지 않는다. 서버 실행에 명령어가 필요하다는 사실과 사용자가 명령을 호출하는 CLI 제품을 구분한다.

## 차이

| 기준 | 독립 CLI | MCP |
|---|---|---|
| 호출 | 셸 명령과 인자 | 도구 이름과 스키마에 맞춘 인자 |
| 발견 | 도움말·문서·에이전트 지침으로 사용법 전달 | tools/list로 이름·설명·입력 스키마 제공 |
| 출력 | 텍스트 또는 직접 설계한 JSON, 종료 코드 | 프로토콜의 도구 결과·오류·구조화 데이터 |
| 주요 장점 | 터미널·스크립트·CI에서 쉽게 재사용 | AI 클라이언트에 기능을 명시적으로 노출 |
| 운영 비용 | 명령 파서·셸 인용·출력 계약 관리 | 서버 수명·초기화·SDK·연결 오류 관리 |
| 상태 유지 | 파일·DB·서비스로 구현 가능 | 파일·DB·서비스로 구현 가능; 연결은 영속 기억이 아님 |
| 강제성 | 자체적으로 다른 도구 사용을 막지 못함 | 자체적으로 다른 도구 사용을 막지 못함 |
| 토큰 | 도움말과 호출 결과가 비용 | 도구 설명·스키마와 호출 결과가 비용 |

CLI도 JSON과 동일한 완료 검사 로직을 제공할 수 있다. MCP가 항상 더 저렴하거나 더 강제적이어서 선택한 것이 아니다. Project Brain의 주 사용자가 AI와 Unity UI이며, 반복적인 맥락 조회·작업 상태 변경을 도구 계약으로 노출하는 것이 목적에 더 잘 맞기 때문에 선택한다.

## 확인한 공식 근거

- [Codex MCP 문서](https://learn.chatgpt.com/docs/extend/mcp?surface=cli): 로컬 stdio 및 Streamable HTTP 지원, 호스트의 MCP 구성, 서버 instructions 지원. 프로젝트 범위 구성은 신뢰된 프로젝트에 적용된다.
- [MCP Tools 명세](https://modelcontextprotocol.io/specification/2025-11-25/server/tools): tools/list, tools/call, 도구 입력 스키마와 결과 규격. 도구 선택은 모델이 수행하며 프로토콜은 특정 사용자 상호작용 방식을 강제하지 않는다.
- [MCP Transports 명세](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports): stdio는 클라이언트가 서버 하위 프로세스를 시작하고 stdin/stdout으로 JSON-RPC를 교환한다. 진단 로그는 stderr로 분리한다.

위 공식 문서의 기능 지원과 현재 설치 환경에서의 실제 연결 성공은 별개다. 최초 구현 단계에서 Codex 도구 노출과 실제 호출을 검증한다.

## 구현 방향

```text
Codex → stdio MCP 호스트 → Unity 연결 계층 → 작업·문서·검증 서비스
Unity Editor UI ─────────────────────────→ 같은 서비스
```

- MCP 서버는 Unity 밖의 작은 프로세스로 둔다. Unity 재컴파일 중에는 준비 중/연결 실패를 반환하고 서버 연결 유지와 재시도를 처리한다.
- Unity 내부가 도메인 상태 변경의 단일 처리자가 된다. UI와 MCP가 상태 파일을 동시에 직접 수정하지 않는다.
- 연결 계층은 MVP에 맞춰 작게 구현하고 요청 ID, 시간 제한, 중복 실행 방지, 재시작 후 상태 조회를 갖춘다.
- 장시간 검증은 시작 요청에 실행 ID를 반환하고 `status`로 결과를 조회한다. 시간 초과를 통과로 해석하지 않는다.
- 도구는 `begin`, `context`, `status`, `update_document`, `verify`, `complete`의 여섯 개로 제한한다. 사람이 확인해야 하는 승인을 MCP에 노출하지 않는다.
- `context`는 검색어/노드 ID, 연결 깊이, 출력량 제한을 받는다. 전체 그래프와 전체 문서를 기본 반환하지 않는다.
- 별도 LLM API 호출 없이 Codex가 이 도구들을 호출한다. 영속 기억은 프로젝트의 저장 자료에 있고 MCP는 이를 읽고 변경하는 통로다.

## 강제성의 정확한 범위

1. 서버 instructions 및 프로젝트 지침으로 begin → 수정 → 문서 갱신 → verify → complete 사용 순서를 안내한다. 이것은 행동 지침이다.
2. 서비스가 해시, 문서 상태, 실제 검증 결과를 확인하고 조건 미충족 완료 요청을 거절한다. 이것은 구현으로 강제하는 작업 완료 조건이다.
3. 일반 파일 편집을 막거나 Codex의 최종 답변을 차단한다고 주장하지 않는다. 변경 감지는 외부 수정까지 포함한다.
4. 저장소 병합을 반드시 막아야 한다면 추후 보호된 CI 검사와 권한 통제가 필요하다. 로컬 메타데이터는 변조 방지 저장소가 아니다.

## 토큰·일정 절약

- CLI 선행 구현 및 이중 인터페이스 개발을 제거한다.
- 도구 설명을 짧게 유지하고 기능별 도구를 무제한 추가하지 않는다.
- 결과는 상태, 변경 요약, 다음 행동을 우선 반환하고 상세 로그는 요청 시만 제공한다.
- 토큰 우위는 미측정이다. 실제 동일 작업의 호출 수·입출력량·누락 정보를 기록한 뒤 평가한다.
- 우선 연결 smoke test를 끝내고 도메인 규칙 → 작업 사이클 → UI 순으로 진행한다. 연결에 문제가 생기면 원인을 기록하고 범위를 재판단하며 조용히 CLI로 대체하지 않는다.
