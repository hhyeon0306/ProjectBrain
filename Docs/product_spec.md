# Project Brain 제품 명세

## 목적과 현재 상태

Project Brain의 최종 목표는 Unity 프로젝트의 설계·구현·검증·작업 이력을 사람과 AI가 같은 구조로 탐색하고, 문서 확인과 실제 검증을 작업 완료 조건에 연결하는 Editor 도구다.

기준 화면은 [최종형 UI 목업](assets/project-brain-final-mockup.png)이다. 도메인 계층 그래프, 왼쪽 탐색, 오른쪽 상세 패널, 다크 테마와 종류별 색상을 최종 목표로 유지한다. 마감 전 최소 구현과 최종 목표는 구분한다. 목업의 파일명·테스트 수·토큰 절감량은 예시이며 실제 성과가 아니다.

2026-09-06 현재: 기존 문서 UI와 관계 그래프 시제품, 범용 저장소 및 v2 비파괴 이관은 구현됐다. 실제 노드는 Code 7개·Document 7개·Image 1개, 관계 26개다. 새 계층 UI, Brain 전용 MCP 도구, 작업·문서 확인·검증 완료 규칙은 미구현이다. A1 필수 JSON 필드 검증·재현성 보완 항목은 [작업표](task.md)의 A1-R에 남아 있다.

## Second Brain의 핵심 가치와 초기 수용 기준

사용자가 원하는 것은 AI가 매 세션 여러 문서를 처음부터 읽지 않고 작업을 이어가며, 현재 코드에 관련된 코드·설계·결정을 그래프로 빠르게 찾는 Second Brain이다. 그래프 화면과 완료 검사만으로 이 목표가 달성되지는 않는다.

다음은 구현할 요구사항이며 현재 기능이 아니다.

- 작업 기억: 목적·대상·진행 상황·결정과 근거·미해결·다음 행동을 지속 저장한다. 새 세션은 활성 작업 요약과 필요한 원본 참조로 재개한다. begin이 기존 활성 작업을 조용히 덮어쓰지 않게 재개 계약을 정한다.
- 관련 맥락: 선택 코드/Feature에서 관계 종류·방향·출처를 유지해 필요한 설명과 관련 코드를 선별한다. 탐색 깊이·정렬·분량 제한·생략 이유·추가 조회 방법을 정한다. 수동 관계를 자동 코드 분석 결과로 표현하지 않는다.
- 최신성: 설명과 관계가 어느 코드 상태를 근거로 작성됐는지 연결하고 변경 시 재확인 대상으로 표시한다. 오래된 자료를 확정 사실로 반환하지 않는다. 자동으로 의미가 교정된다고 주장하지 않는다.

초기 검증은 하나의 실제 작업을 등록·요약 저장 → 새 세션에서 재개 → 관련 맥락만 조회 → 코드 변경 후 오래된 자료 표시로 수행한다. 반환 내용의 정확성·생략과 실제 조회량을 확인한다. 고급 UI 완성 전에 W1/M2a와 공통 서비스를 통해 이 흐름을 검증한다. 토큰 절감·효율 향상은 비교 측정 전에는 목표다.

## 최종 탐색 구조

```text
Project
└─ Domain
   └─ Feature
      ├─ Code
      ├─ Document / Image
      ├─ Evidence (Test / Build Result)
      ├─ Activity
      └─ Reference
```

사람은 Project/Domain에서 Feature를 찾고, 역할·설계 의도·주의사항·이미지·관련 코드·검증 결과·작업 이력·참고 자료를 확인한다. 관계는 종류와 방향을 유지해 양쪽에서 탐색한다. 파일·문서가 바뀌면 확인·검증이 오래됐음을 표시하고 완료할 수 없는 이유를 설명한다. 이는 최종 동작 요구사항이며 현재 구현 상태를 뜻하지 않는다.

데이터 계약은 [architecture.md](architecture.md)를 따른다. contains 계층과 의미 관계를 구분하고, 순환이나 잘못된 데이터가 UI 무한 탐색으로 이어지지 않도록 한다.

## 마감 전 최소 시연

1. Project → Player → 소수 Feature → 실제 Code/Document/Image로 이동한다. 문서가 없다면 없다고 표시하고 코드를 설계 설명으로 꾸미지 않는다.
2. Codex가 brain_begin/context로 작업 목적·대상과 제한된 맥락을 확인한다.
3. 작은 코드 변경 뒤 brain_status가 차이를 표시하고 brain_complete가 미확인 문서·미검증을 이유로 거절한다.
4. 명시적 문서 확인과 현재 코드의 필요한 검증을 마친 후 완료 성공을 시연한다. 검증 뒤 다시 변경하면 이전 결과로 완료하지 못한다.
5. 실제 호출 결과·화면·검증 범위·직접 구현 및 재사용 영역을 포트폴리오에 남긴다.

1은 A2, 2~4는 W/M/V 단계다. A2만으로 전체 시연을 완료했다고 기록하지 않는다. 마감에 못 맞춘 부분은 미구현으로 설명하며 제출을 지연시키거나 가짜 성공 기록으로 채우지 않는다.

## AI 도구 계약: 모두 계획, 현재 미구현

| 도구 | 역할 | 시연 우선순위 |
|---|---|---|
| brain_begin | 목적·대상·시작 스냅샷 등록 | 필수 |
| brain_context | 노드/검색어 기반 제한된 주변 맥락, 생략 표시 | 필수 |
| brain_update_task | revision 확인 후 진행·결정·미해결·다음 행동 저장 | 작업 재개에 필수 |
| brain_status | 변경·문서 확인·검증 상태와 다음 행동 | 필수 |
| brain_update_document | 문서 갱신, AI 작성과 사람 확인 구분 | 완전한 편집 흐름 |
| brain_apply | 예상 해시가 맞는 파일 수정·이력 기록 | 완전한 편집 흐름 |
| brain_verify | 실제 Unity 검증 요청·실행 ID·최종 결과 | 필수 |
| brain_complete | 현재 기준으로 조건 검사·거절 또는 완료 | 필수 |

brain_apply가 없는 초기 시연은 Codex의 일반 파일 편집을 사용하고 Brain이 이를 감지한다고 명시한다. 이를 brain_apply 시연으로 표현하지 않는다. 사람이 문서를 확인하는 경로는 UI에 별도로 필요하며 AI 문서 저장을 승인으로 간주하지 않는다.

기존 IvanMurzak/Unity-MCP 0.90.0에 얇은 도구를 추가한다. 별도 서버·제품 CLI를 만들지 않는다. MCP는 파일 편집을 가로채지 않으며 Brain의 완료 요청만 검사한다. Git 병합·Codex 답변·파일 직접 편집을 강제로 막는 보안 경계는 아니다.

## 완료 조건: 목표

- begin 기준선 이후 감시 범위의 변경을 검사하고, 미등록·허용 범위 밖 변경을 숨기지 않는다.
- 변경된 Feature의 필수 문서는 현재 문서 내용과 코드 스냅샷에 대해 확인돼야 한다.
- 필요한 컴파일·테스트가 현재 대상 스냅샷에서 실제 성공해야 한다. compile, editmode, playmode를 구분한다.
- 검증 중·후 코드 변경 또는 문서 변경은 관련 확인·검증 상태를 무효화한다.
- 사람 확인이 필요한 항목은 AI가 대신 승인하거나 정책을 낮춰 우회할 수 없어야 한다.
- 테스트 0개, 미실행, 실행 중, 실패, 시간 초과, 취소, 오래된 결과를 성공으로 표시하지 않는다.
- 실패 원인과 보완 행동을 반환한다. 해시는 내용의 의미적 정확성까지 증명하지 않는다.

정확한 감시·허용 범위, 검토 기록, 검증 정책은 W1/W2/V1 계약에 명시해야 한다. 현재 BrainNode.status는 위 조건을 구현한 상태 머신이 아니다.

## 화면 구성과 단계

| 영역 | 최종 목표 | A2의 최소 범위 |
|---|---|---|
| 왼쪽 | 종류 필터·프로젝트 탐색·즐겨찾기·목록 | Project/Domain/Feature 선택과 최소 종류 구분 |
| 중앙 | 계층 그래프·의미 관계·검색·확대·이동 | Player 계층과 선택·복귀, 방향·출처 표시 |
| 오른쪽 | 역할·설계·이미지·관련 코드·증거·활동·참고 | 저장된 설명·자료 탐색, 없는 증거는 미검증 |
| 상단 | 작업·문서·컴파일·테스트 상태 | 미구현 상태를 통과 표시로 대신하지 않음 |
| 하단 | AI의 실제 조회 범위·맥락 정보 | 데이터가 없으면 미측정. 가짜 절감 수치 금지 |

UI Toolkit을 사용한다. 기존 방사형 그래프는 Code 중심 시제품이다. 전체 도메인·고급 검색·즐겨찾기·완성형 시각 효과는 U1에서 확장한다. 목업의 입력창을 이유로 별도 채팅/LLM API 기능을 자동 추가하지 않는다. AI 실행은 우선 Codex와 MCP를 통한다.

## 저장·운영 요구사항

- 파일 단위 원자 저장과 손상 파일 보호. 여러 파일 전체의 트랜잭션이나 동시 편집 보장은 현재 없다.
- GUID/경로 변경·삭제·손상·미지원 스키마를 숨기지 않는다. A1의 missing은 이관 시점 상태이며 실시간 감시는 W1 이후다.
- docs는 원본·레거시 UI 데이터, nodes/relations는 새 모델이다. 자동 동기화되지 않는다. A2에서 새 화면의 저장 기준과 기존 창의 경계를 명시한다.
- Library/Temp/Logs/외부 PackageCache는 감시 제외 대상이다. 구체적 범위와 meta 정책은 W1에서 정한다.
- AI 맥락은 요약·제한된 깊이와 분량으로 반환하고 생략을 알린다. 원본 이미지와 긴 로그는 필요할 때만 조회한다.
- 성능·토큰 절감은 동일 작업 비교 측정 전에는 가설이다.

## 검증·완료 표현

A1의 25/18/14는 Unity에서 직접 호출한 C# 자체 검사 함수의 체크 항목 수다. NUnit/EditMode 테스트 57개, 게임 플레이 검증, 화면 검증, Brain의 Evidence 57건을 뜻하지 않는다. 검증은 실행 시점의 코드에만 적용한다.

AGENTS를 Brain **사용 중심**으로 전환하려면 begin/context/apply/update_document/verify/status/complete의 실제 전체 흐름, 필요한 사람 확인, 성공 및 거절 사례를 모두 검증해야 한다. 최소 시연만 완료한 경우 개발 지침을 유지한다.

포트폴리오에는 검증된 범위, 알려진 한계, 본인의 판단과 AI의 기여, 직접 구현한 Brain 영역과 재사용한 Unity-MCP 및 라이선스를 구분한다. 기존 Unity 포트폴리오 적용·호환성은 별도 검증 전에는 주장하지 않는다.

## 기반 검토의 현재 판정

2026-09-06 최종 대화에서 Second Brain을 구현할 기초 설계와 방향은 충분하며 구현으로 진행 가능하다고 판단했다. 전면 재설계나 추가 전면 검토는 필요하지 않다. 작업 기억·관련 맥락·최신성의 상세 계약은 구현하면서 확정한다. 제품 완성이나 무결함을 뜻하지 않는다. [기반 검토 보고서](reviews/2026-09-06-project-review.md)의 불완전 JSON 수용·clone 이관 거절·UI 오류 경계 결함은 A1-R/F2의 미해결 구현 태스크로 유지한다.
