# Brain 구현 작업 및 다음 세션 인계

## 최종 목표와 결정
Unity 그래프에서 사람은 설계·참조·검증 상태를 확인하고, Codex는 같은 데이터를 MCP 도구로 조회·수정한다. 연결 기반은 설치한 IvanMurzak/Unity-MCP를 재사용한다. Tool은 실행 기능, Skill/AGENTS는 사용 순서를 안내하는 지침이다. MCP가 파일 편집을 자동 가로채지는 않는다.

마감: 2026-09-07 16:00. 9/6에는 지원서·기존 PPT 정리 시간을 확보한다. 사용자는 토큰·시간 절약을 강조했고 리셋권 2개 보유를 알렸으며 필요할 때 사용을 승인했다. 현재 잔량은 이미지의 과거 수치로 추정하지 말고 필요 시 확인한다. 아직 리셋권은 사용하지 않았다.

### T1 — 골격
기본 경로는 Packages/com.projectbrain.editor, 예제는 Assets/ProjectBrainDemo. 생성 전 기존 파일과 asmdef, 설치된 MCP 확장 API를 필요한 범위만 확인한다. 핵심 로직은 Editor UI 및 MCP 타입에 의존하지 않도록 한다. 자료는 .projectbrain에 JSON으로 저장하고 스키마 버전을 둔다. 원자적 저장과 실패 처리를 적용한다. MVP에서는 동시 활성 작업 하나로 제한해 복잡도를 줄인다.

데이터: 노드 ID(Unity GUID 우선), 상대 경로, 코드 SHA-256, 역할/설계 의도/주의사항, 문서 확인 해시, 관계와 출처. 작업은 ID/목적/대상/시작 스냅샷/변경 목록/상태를 가진다. 검증은 종류/실행 ID/대상 스냅샷/결과/로그 경로를 가진다.

완료 기준: 예제 노드와 작업을 저장하고 다시 읽을 수 있다. 없는 파일, 삭제, 이름 변경을 조용히 누락하지 않는다.

### T2 — 실제 규칙
감시 폴더를 명시적으로 정한다. Library/Temp/Logs 및 외부 패키지는 제외한다. 파일 추가·삭제·수정은 스냅샷 비교로 탐지한다. 이벤트 감지는 빠른 UI 갱신 수단이고 완료 시 다시 검사한다.

코드가 바뀌면 문서 확인과 검증을 무효화한다. 완료 요청은 미등록/범위 밖 변경, 문서 미확인, 검증 미실행·실패·오래됨을 구분해 거절 이유와 다음 행동을 반환한다. verify가 없는 초기 단계는 검증 미실행으로 정직하게 거절한다. 성공을 가짜로 채우지 않는다.

완료 기준: 외부 편집 감지, 해시 무효화, 실패 완료의 핵심 테스트 통과. 해시가 문서 의미의 정확성을 보장하지 않는 한계를 기록한다.

### T3 — 첫 수직 구현
설치된 MCP의 AiToolType/AiTool 선언과 메인 스레드 실행 패턴을 확인해 얇은 어댑터를 만든다. 공개 이름은 brain_begin, brain_status, brain_complete. 기존 연결을 변경하지 않는다. 도구가 즉시 노출되는지 실제 확인하고 재연결 필요 여부는 관찰한 결과로 안내한다.

시연: Codex가 begin 호출 → 예제 C# 파일 외부 수정 → status에 변경 표시 → complete 거절. 정상 MCP 연결과 실제 업무 규칙 동작을 함께 증명한다.

### T4 — AI가 Brain으로 편집
- brain_context: 검색어/노드 ID, 기본 연결 1단계, 출력량 제한. 파일 경로·요약 우선, 생략 정보 표시.
- brain_apply: 작업 ID, 파일 경로, 예상 기존 해시, 변경 내용. 첫 버전은 작은 텍스트 파일 전체 교체로 제한 가능. 대상 루트 밖 경로 거절, 오래된 해시 거절, 변경 이력 기록. 변경 전후 해시 저장. 임의 명령 실행 기능을 섞지 않는다.
- brain_update_document: 역할·의도·주의사항 갱신. AI 작성과 사람 확인을 구분한다. 필수 사람 승인은 AI가 대신하지 못하게 한다.

완료 기준: Brain으로 수정 성공과 오래된 해시 수정 거절. 일반 파일 편집으로 우회한 변경도 T2가 잡아낸다.

### T5 — 검증
brain_verify는 실제 Unity 컴파일·테스트를 실행하거나 실행기에 요청한다. 긴 작업은 실행 ID를 반환하고 status에서 확인한다. 컴파일 실패, 테스트 실패, 미실행, 시간 초과, 재컴파일 중을 구분한다. 검증 후 변경되면 결과 무효. 초기 전체 감시 스냅샷 검사로 보수적으로 처리한다.

완료 기준: 미검증 완료 거절, 실패 완료 거절, 검증 후 수정 시 거절, 현재 코드의 필요한 검증과 문서 확인 완료 시 성공. UI에서 승인해야 하는 조건이 있다면 실제 사용자 확인을 받아야 한다.

### T6 — 검사 및 UI
검사 스크립트는 상태를 조회·평가하고 미완료 시 비정상 종료한다. 별도 제품 CLI/MCP 서버를 새로 만드는 작업으로 확대하지 않는다. 가능하면 같은 검사 서비스 호출, 불가하면 규칙 복제보다 보고서 검사 범위를 명확히 한다.

UI: 목록/간단한 관계 그래프/선택 노드 문서/검토 필요/완료 조건. 자동 참조 분석보다 수동 관계와 출처부터 완성 가능. 실패 상태에서 완료 불가, 외부 변경 후 상태 갱신 확인.

### T7 — 사용 단계 전환
실제 MCP 호출로 begin/context/apply/update_document/verify/status/complete 흐름을 모두 검증한 후 루트 AGENTS를 사용 절차 중심으로 개정한다. 사용자는 매번 Brain을 언급하지 않아도 지침을 따르는 것이 목표지만 100% 준수를 보장하지 않는다. 변경 감지 및 완료 거절이 실제 보완 장치다. CI/권한 제어 없이 일반 파일 편집이나 병합까지 차단했다고 주장하지 않는다.

최종 자료: 설치·사용법, 도구 의존성 및 라이선스 확인, 직접 구현/재사용 영역, 아키텍처, 성공·실패 시연 스크린샷, 검증 로그, 맥락 입력량 비교. 성능·토큰 절감 수치는 측정 전 주장하지 않는다. 기존 Unity 포폴 적용은 별도 브랜치에서 버전 확인 후 작은 기능 하나만 한다.

## 현재 구현 범위 — 스크립트 문서 저장
- Window/Project Brain/Script Document에서 Assets의 C# 스크립트를 지정하고 역할·설계 의도·주의사항을 편집·저장·다시 읽는다.
- .projectbrain/docs/<Unity GUID>.json에 schemaVersion, scriptGuid, lastKnownPath, role, designIntent, cautions, relatedScriptGuids, savedCodeHash, updatedUtc 저장.
- GUID로 현재 경로를 조회한다. savedCodeHash는 저장 당시 코드이며 사람의 검토 승인이나 테스트 통과가 아니다.
- 손상된 JSON/미지원 스키마/잘못된 GUID를 거절하고 원본을 유지한다. 임시 파일 후 교체로 저장한다.
- 관련 코드 UI는 구현. 변경 감지 표시, 작업 상태, MCP 도구, 자동 검증은 아직 미구현이다. 기존 지침의 Brain 미구현 문구는 전체 업무 흐름이 미구현이라는 의미이며 문서 저장은 구현됐다.
- 검사: Unity batchmode -executeMethod ProjectBrain.DocumentStoreChecks.RunBatch. fixture는 기존 Readme 스크립트와 OS 임시 문서 폴더를 사용하고 실제 문서는 변경하지 않는다.

## Scripts 구조와 UI 방식
- Assets/Scripts: Core(기반), Gameplay(게임 기능), UI(게임 UI), Infrastructure(외부 연동/저장), Utilities(보조), Tests(샘플). 빈 폴더는 .gitkeep으로 Git 유지.
- Tests/BrainDocumentSample.cs는 문서 연결용 샘플이며 자동 테스트가 아니다. 호출 시에만 이동하며 씬을 자동 변경하지 않는다.
- Brain 문서 창은 UI Toolkit CreateGUI 기반. 데이터 저장 서비스와 분리하며 재컴파일 시 편집 데이터를 직렬화해 유지한다.

## 이미지 문서와 그래프 방향 (2026-09-04 사용자 결정)
- 현재 문서 UI는 초기 편집기. 최종 UI는 중앙 관계 그래프와 선택 문서 패널이며 UI Toolkit 사용.
- 이번 구현: schemaVersion 2, body 본문, imageGuids 첨부 이미지, relatedScriptGuids 수동 관계. v1은 읽을 때 메모리에서 v2로 변환하고 명시적 저장 전 원본을 바꾸지 않는다.
- 이미지는 Assets의 Texture2D를 ObjectField로 선택하거나 드래그해 연결. 외부 파일은 먼저 Project 창으로 가져온다. GUID로 추적하며 누락을 표시한다. 연결 제거는 이미지 파일 삭제가 아니다.
- 본문은 여러 줄 일반 텍스트. Markdown/코드 표기를 저장할 수 있지만 서식 렌더링, 이미지 본문 내 배치, 캡션, 독립 문서 노드는 아직 미구현.
- 현재 문서는 스크립트당 하나. 관련 문서 열기는 연결된 스크립트의 문서를 열거나 새로 작성한다. 자동 코드 분석 결과가 아닌 사용자가 지정한 방향성 관계다.
- 다음: 작은 그래프에서 노드/선, 선택, 문서 열기 구현. 이후 이동/확대·축소/검색과 변경·검증 상태 연결. 전체 노드 밀집도보다 선택 코드 주변 관계 탐색을 우선한다.
- AI 맥락은 본문·관계·이미지 식별자를 우선하고 실제 이미지 데이터는 필요할 때 조회하도록 후속 MCP 설계. 토큰 절감 수치는 아직 측정하지 않음.

## 2026-09-05 관계 그래프 첫 구현
- 같은 창의 왼쪽에 선택 코드와 직접 연결한 코드 노드/선을, 오른쪽에 문서 편집기를 표시한다. 노드 클릭 시 미저장 확인 후 해당 문서로 이동한다.
- 방사형 고정 배치, GUID 기반 이름/경로, 누락 코드 비활성 표시. 자동 의존성 분석이나 검증 상태 표시는 아니다. 확대·이동·전체 검색 및 많은 노드 배치 개선은 후속 작업이다.
- 관계 탐색은 양방향이다. A 문서가 B를 관련 코드로 등록하면 B를 선택했을 때도 들어오는 관계 A를 표시한다. 저장 데이터는 중복 수정하지 않고 그래프 조회 시 양방향으로 합친다.
