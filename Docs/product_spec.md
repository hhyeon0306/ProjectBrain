# Project Brain 제품 명세

## 목적

Project Brain은 Unity 프로젝트의 설계와 구현 증거를 사람과 AI가 같은 구조로 탐색하는 Editor 도구다. 사람은 전체 아키텍처에서 코드·문서·테스트·작업 이력을 확인하고, Codex는 같은 데이터를 Unity-MCP Tool로 제한적으로 조회·수정한다.

기준 화면은 [최종형 UI 목업](assets/project-brain-final-mockup.png)이다. 목업의 파일명, 테스트 수, 토큰 절감량은 시각 예시이며 측정 결과가 아니다.

## 핵심 탐색 구조

```text
Project
└─ Domain
   └─ Feature
      ├─ Code
      ├─ Document / Image
      ├─ Test / Build Result
      ├─ Work Activity
      └─ Reference
```

- 전체 화면은 Project에서 Domain과 Feature로 내려가는 아키텍처 지도를 제공한다.
- 선택 노드의 역할, 설계 의도, 주의사항, 관련 코드, 문서, 이미지, 검증 결과, 작업 이력, 참고 자료를 상세 패널에 표시한다.
- 관계의 방향과 종류를 보존하면서 양쪽 노드에서 탐색할 수 있다.
- 코드·문서 변경 후 확인 및 검증 상태를 무효화하고 필요한 다음 행동을 표시한다.
- 데이터 계약과 저장 형식은 [architecture.md](architecture.md)를 기준으로 사용한다.

## 사람의 작업 흐름

1. Project 또는 Domain에서 관련 Feature를 찾는다.
2. 설계 문서와 아키텍처 이미지를 확인한다.
3. 관련 코드, 의존 관계, 최근 작업 이력과 참고 자료를 탐색한다.
4. 현재 코드에 대응하는 컴파일·테스트 결과를 확인한다.
5. 문서 확인이나 검증이 오래됐으면 완료할 수 없는 이유를 확인한다.

## AI의 작업 흐름

1. `brain_begin`: 작업 목적과 대상 노드를 등록하고 시작 스냅샷을 만든다.
2. `brain_context`: 검색어 또는 노드 ID로 제한된 주변 맥락을 받는다.
3. `brain_apply`: 예상 해시가 일치하는 파일만 수정하고 변경 이력을 남긴다.
4. `brain_update_document`: 설계 문서를 갱신하되 AI 작성과 사람 확인을 구분한다.
5. `brain_verify`: Unity 컴파일·테스트를 실행하고 대상 스냅샷과 결과를 연결한다.
6. `brain_status`와 `brain_complete`: 누락 조건을 확인하고 충족되지 않으면 완료를 거절한다.

기존 IvanMurzak/Unity-MCP 0.90.0의 연결과 도구 확장 API를 사용한다. 별도 MCP 서버나 제품 CLI는 만들지 않는다. MCP는 일반 파일 편집을 가로채지 않으며 외부 변경 감지와 완료 검사가 누락을 드러낸다.

## 완료 규칙

- 등록되지 않았거나 작업 범위 밖인 변경이 없어야 한다.
- 변경된 Feature의 필수 설계 문서가 현재 코드 기준으로 확인돼야 한다.
- 필요한 컴파일과 테스트가 현재 코드 스냅샷에 대해 성공해야 한다.
- 검증 후 코드가 바뀌면 이전 결과는 무효다.
- 사람 확인이 필요한 조건은 AI가 대신 승인할 수 없다.
- 컴파일 성공을 테스트 성공으로 표현하지 않는다.

## UI 범위

- 상단: 프로젝트, 검색, 현재 작업, 문서·컴파일·테스트 상태.
- 왼쪽: Project/Domain/Feature 및 노드 종류 필터.
- 중앙: 계층과 의미 있는 관계를 보여주는 그래프. 선택 중심 확대, 이동, 검색.
- 오른쪽: 역할·설계·아키텍처 이미지·관련 코드·증거·작업 이력·참고 자료.
- 하단: AI가 실제로 조회한 노드 범위와 측정 가능한 맥락 사용 정보.

초기 UI는 UI Toolkit을 사용한다. 현재 방사형 스크립트 관계 그래프는 데이터·탐색 검증용 시제품이며 최종 화면이 아니다.

## 비기능 요구사항

- `.projectbrain` 데이터는 Git으로 추적 가능하고 원자적으로 저장한다.
- GUID·경로 변경, 파일 삭제, 손상 JSON, 지원하지 않는 스키마를 조용히 누락하지 않는다.
- Library, Temp, Logs, 외부 PackageCache는 변경 감시에서 제외한다.
- AI 기본 맥락은 요약과 제한된 관계 깊이만 포함한다. 이미지 원본과 긴 로그는 필요할 때만 조회한다.
- 성능과 토큰 절감 수치는 실제 비교 측정 전에는 포트폴리오에 사용하지 않는다.

## 포트폴리오 완료 증거

- Project→Domain→Feature→코드·문서·검증으로 이어지는 실제 탐색 화면.
- Codex가 Brain 맥락을 조회하고 코드를 수정한 성공 사례.
- 외부 변경, 문서 미확인, 검증 미실행 때문에 완료가 거절되는 사례.
- 현재 코드에 대한 컴파일·테스트 성공 기록.
- 직접 구현한 Brain 영역과 재사용한 Unity-MCP 영역 및 라이선스 설명.
